## Objective

Separate operational Panel typography from expressive Notebook typography: use a conventional system UI stack for navigation, body copy, forms, controls, metadata, Social, Settings, Chat, and technical content while retaining Xiaolai for short Notebook page and section headings.

## Problem Evidence

- The renderer root currently makes Xiaolai the first font for every window and descendant.
- Dense Settings, Social, Chat, form, code, and diagnostic content therefore inherits a handwritten face.
- The approved UI/UX specifications classify this as incomplete and require conventional UI typography for operational content.
- UI-002 now provides a semantic distinction between taped narrative headings and untaped operational `PaperCard` headings that UI-003 can use without guessing by page.

## Relevant Specifications

- `docs/ui-ux/ART_DIRECTION.md` — visual hierarchy, typography roles, prohibited global handwritten typography.
- `docs/ui-ux/UI_LAYER_SYSTEM.md` — Narrative Notebook and Operational Paper layers.
- `docs/ui-ux/COMPONENT_VISUAL_RULES.md` — shell, Notebook headings, PaperCard, forms, Chat, and Social.
- `docs/ui-ux/ASSET_REQUIREMENTS.md` — existing Xiaolai asset and unverified SetoFont constraints.
- `docs/ui-ux/MOTION_LANGUAGE.md` — preserve current transitions and reduced-motion behavior.

## Scope

- Add `--font-ui` and `--font-handwritten` semantic design tokens.
- Apply `--font-ui` at the `.panel-shell` boundary and to native Panel controls.
- Preserve `--font-handwritten` for Panel Notebook page H1s, taped section titles, and short StickyNote titles.
- Keep untaped operational `PaperCard` headings and all long-form/user-authored content in the UI role.
- Add source-policy and Electron computed-style coverage.
- Verify Settings, Social, Chat, Home, 760 px Simplified Chinese, accessibility, and one non-Panel surface.

## Out of Scope

- New, replaced, downloaded, renamed, or redistributed font files.
- SetoFont adoption, licensing work, or a new monospace token.
- Global redesign of renderer typography outside the Panel.
- Font size, line height, weight, spacing, color, layout, localization, motion, or behavior changes.
- Settings, Social, or Chat refactors; new component variants; UI-001 or UI-002 behavior changes.
- Network repository, server, database, migration, or credential changes.

## Implementation Plan

1. Define the two semantic tokens while preserving the existing non-Panel root stack.
2. Scope the UI role to `.panel-shell` and its native controls.
3. Restore the handwritten role only on semantic short expressive selectors.
4. Add focused source-policy and Electron computed-style tests.
5. Capture and visually review deterministic evidence for all required surfaces.

## Required Runtime States

1. Settings AI in English: operational heading and controls use UI typography; page H1 stays handwritten; focus and layout remain unchanged.
2. Settings Companion in Simplified Chinese: operational headings/body use system UI/CJK fallback; page title remains expressive; no missing glyphs.
3. Social populated smoke state: authored taped heading remains handwritten; account, lookup, relationship, and Published Companion content use UI typography; UI-001 and UI-002 remain intact.
4. Chat deterministic history: user/Companion messages, metadata, search, and composer use UI typography; bubble assets/alignment remain unchanged.
5. Home narrative state: page and taped section titles remain handwritten; card body copy uses UI typography; tape remains intact.
6. Simplified Chinese Settings AI at 760 px: no clipping, missing glyphs, or horizontal page overflow.
7. Settings, Social, and Chat retain heading semantics, accessible names, visible focus, selectable text, and zero new critical/serious axe violations.
8. Reduced-motion and Panel page transitions remain unchanged.
9. One Creation or Companion Quick Actions surface is not intentionally restyled by Panel-scoped selectors.

## Acceptance Criteria

- `--font-ui` and `--font-handwritten` are defined in the design-token system.
- `--font-ui` does not use Xiaolai as its primary face; `--font-handwritten` preserves Xiaolai with safe fallbacks.
- `.panel-shell`, Panel buttons, inputs, textareas, and selects resolve to the UI role.
- Settings, Social, Published Companion, Chat content, operational headings, and body copy resolve to the UI role.
- Notebook page H1s, taped section titles, and short StickyNote headings resolve to the handwritten role.
- Untaped `PaperCard` headings resolve to the UI role.
- UI-001 friend lookup and UI-002 intentional tape behavior remain unchanged.
- No new font, asset, dependency, SetoFont usage, or visual/motion redesign is introduced.
- English and Simplified Chinese remain readable; the 760 px Panel has no horizontal overflow.
- Focused computed-style tests, typecheck, architecture checks, full unit suite, build, focused Electron test, and full Electron suite pass, apart from disclosed existing credential-gated skips.

## Risks

- Native `select` elements may not inherit the Panel font without an explicit scoped rule.
- Broad heading selectors could incorrectly make operational headings handwritten.
- System fallback metrics could reveal wrapping changes at narrow widths.
- A global token application could unintentionally restyle Creation or Overlay windows.
