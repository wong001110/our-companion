# Plan: Move animationConfig & companionBehavior out of ann/ + add missing configs

## Context

`character/ann/` currently holds character-specific code, but `animationConfig.ts` and `companionBehavior.ts` are used generically — the `createCompanionAnimations()` function already accepts a dynamic `assetRoot` parameter, making it character-agnostic. The `ann/` subfolder should only contain Ann-specific overrides, not shared infrastructure.

### Part 4 — Wire the new animations into the state machine

Update `CompanionCanvas.tsx:282-297` (`stateToIntent()`) to map the new animations:

| Trigger | → Animation |
|---|---|
| `coreState === 'listening'` | `Listening` (already mapped to `Think` — change to `Listening`) |
| `coreState === 'talking'` + mood thinking | `Talk_Thinking` |
| `coreState === 'talking'` + mood concerned | `Talk_Concerned` |
| `coreState === 'talking'` (default) | `Talk_Neutral` (keep) |
| user typing detected (via `userIsTyping` prop) | `Waiting_Response` |
| app start (first mount) | `Enter` |
| app close (before unload) | `Leave` |
| music playing detected | `Music_Idle` |
| walk directions | `Walk_Up`/`Walk_Down`/diagonal variants based on position delta |

**Note:** The `Enter`/`Leave` animations need lifecycle hooks in `App.tsx`:
- `Enter`: fire on companion first mount / session start
- `Leave`: fire `Leave` animation, wait for it to complete, then call `window.close()`

### Part 5 — Clean up `DEFAULT_ASSET_ROOT`

`AssetResolver.ts:33` has `DEFAULT_ASSET_ROOT = 'assets/companions/ann'`. This is fine to keep as a fallback — it's already overridden per-companion via the `assetRoot` prop from `CompanionProfile`. No change needed here.
