# Derive Frame Dimensions from Image in SpriteAnimator

## Problem

The animation display uses hardcoded `frameWidth`/`frameHeight` (300x300) from `animationConfig.ts`, while the creation display correctly derives frame size from the image itself (`naturalHeight` for both). The user wants consistency — animation should also use the image's actual dimensions.

## Change

**File:** `apps/desktop/renderer/src/character/SpriteAnimator.ts`

In the `load()` method, after the image loads, override `this.frameWidth` and `this.frameHeight` with `image.naturalHeight` (since frames are square), then compute `columns` from `naturalWidth / naturalHeight`.

### Before (lines 52-63):
```typescript
image.onload = () => {
    if (this.cancelled) { resolve(); return; }
    this.image = image;
    this.columns = this.columns || Math.floor(image.naturalWidth / this.frameWidth);
    this.rows = this.rows || Math.floor(image.naturalHeight / this.frameHeight);
    this.totalFrames = this.columns * this.rows;
    resolve();
};
```

### After:
```typescript
image.onload = () => {
    if (this.cancelled) { resolve(); return; }
    this.image = image;
    this.frameHeight = image.naturalHeight;
    this.frameWidth = image.naturalHeight;
    this.columns = this.columns || Math.floor(image.naturalWidth / image.naturalHeight);
    this.rows = this.rows || 1;
    this.totalFrames = this.columns * this.rows;
    resolve();
};
```

## Impact

- `animationConfig.ts` still passes `frameWidth: 300, frameHeight: 300` but they get overridden in `load()`
- No other files need changes
- Animation will now correctly handle spritesheets with any square frame size, not just 300x300
